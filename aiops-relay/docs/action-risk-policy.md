# 위험 등급 판정 가이드라인

이 문서는 AIOps 파이프라인이 알럿 발생 시 **"자동 실행 / 1인 승인 / 전체 승인"** 중 어느 경로를 탈지 정하는 기준을 정의한다. 코드(`config/actions.js`)는 이 문서를 그대로 구현한 것이며, 등급 기준을 바꿀 때는 이 문서와 코드를 함께 수정한다.

---

## 1. 핵심 원칙

> **최종 등급 = MAX(알럿 심각도 등급, 대응 조치 위험도 등급)**

알럿이 아무리 가벼워도 대응 조치 자체가 위험하면 그 조치 기준을 따르고, 반대로 알럿이 심각해도 조치가 안전하면 조치 기준을 우선한다. 항상 **"더 위험한 쪽"**을 기준으로 삼는다.

---

## 2. 대응 조치 위험도 (Action Risk) 분류

조치가 **되돌리기 쉬운지, 부작용 범위가 얼마나 넓은지**를 기준으로 3단계로 나눈다.

| 등급 | 정의 | 예시 |
|---|---|---|
| 저위험(LOW) | 즉시 되돌릴 수 있고 부작용이 해당 프로세스 내로 국한됨 | 프로세스/스레드 재시작, 캐시 클리어, 커넥션 풀 리셋, 로그 레벨 변경 |
| 중위험(MEDIUM) | 되돌릴 수 있으나 서비스에 순간적 영향(재시작 중 요청 실패 등)이 있음 | 컨테이너 재기동, 오토스케일 조정, 특정 인스턴스 격리 |
| 고위험(HIGH) | 되돌리기 어렵거나 데이터/보안에 영향 | 배포 롤백, DB 스키마/데이터 변경, 트래픽 라우팅 변경, 인증/권한 설정 변경 |

**하드 룰(점수와 무관하게 항상 적용)**
- 아래 조치는 알럿 심각도가 아무리 낮아도 **최소 고위험**으로 취급한다:
  - 배포 롤백 / 재배포
  - DB 스키마 변경, 데이터 삭제/수정
  - 보안 설정(인증, 권한, 방화벽) 변경
  - 프로덕션 트래픽 라우팅 변경

---

## 3. 알럿 심각도 (Alert Severity) 분류

Grafana 알럿 규칙에 설정된 임계값 초과 정도, 지속 시간, 영향 범위를 기준으로 점수화한다.

```
severity_score = (임계값 초과 배율 + 지속 시간 가중치 + 영향 범위 가중치) / 3
```

| 점수 구간 | 등급 |
|---|---|
| 0 ~ 2.4 | 저위험 |
| 2.5 ~ 3.9 | 중위험 |
| 4.0 ~ 5.0 | 고위험 |

지금 단계에서는 정교한 자동 계산 대신, **알럿 규칙별로 미리 심각도를 수동 지정**한다 (아래 4번 표). 추후 실제 트래픽 데이터가 쌓이면 자동 계산 로직으로 고도화한다.

---

## 4. 현재 알럿 3종에 대한 판정표

| 알럿 | 알럿 심각도 | 기본 권장 조치 | 조치 위험도 | **최종 등급** | 처리 경로 |
|---|---|---|---|---|---|
| DB Connection Pool Saturation | **저위험** (일시적 스파이크가 잦고, 리셋만으로 자연 회복되는 신호) | HikariCP 커넥션 풀 리셋 | 저위험 | **저위험** | 자동 실행 |
| JVM Heap Memory High Usage | 중위험 | 애플리케이션 프로세스 재시작 | 중위험 | **중위험** | 1인 승인 |
| HTTP 5xx Error Rate Spike | 고위험 | 원인 특정 전까지 즉시 자동 조치 불가 (코드/배포 이슈 가능성) | 고위험(원인 불명 시 롤백 필요할 수 있음) | **고위험** | 팀 전체 승인 + 가이드라인 제시 |

---

## 5. 처리 경로별 동작 정의

### 저위험 → 자동 실행
- 사전에 정의된 화이트리스트 스크립트만 실행 가능 (임의 명령 실행 금지)
- 실행 후 결과를 Slack에 통보 (승인 요청 아님, 사후 보고)

### 중위험 → 1인 승인
- Slack 메시지에 **승인 / 거부** 버튼 표시
- 담당자 1인이 승인하면 즉시 실행
- 미승인 시 일정 시간(예: 10분) 후 에스컬레이션(고위험 경로로 전환)

### 고위험 → 팀 전체 승인 + 가이드라인 제시
- 자동 조치 없음. AI가 생성한 원인/권장 조치(가이드라인)만 제시
- 팀원 전체(또는 지정된 쿼럼 수) 승인이 있어야 조치 실행 (수동 실행 포함)
- 지금 단계에서는 "자동 실행"까지 만들지 않고, **가이드라인 제시 + 승인 로그 기록**까지만 구현

---

## 6. 향후 확장

- 알럿 심각도 자동 계산 (지금은 수동 지정)
- 새 알럿 추가 시 이 표에 반드시 등록 (등록 안 된 알럿은 기본적으로 고위험으로 처리)
- 조치 실행 이력을 쌓아서, 자동 실행된 조치의 성공/실패율을 추적
